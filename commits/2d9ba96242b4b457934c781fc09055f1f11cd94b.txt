feat: extract ImGui backend into dedicated projects (Vulkan + OpenGL)
Decouple ImGui rendering from concrete Vulkan/GL backend implementations by
creating four new projects that host interfaces and ImGui-specific logic.

New projects:
- IeCoreVulkanInterfaces: IVulkanDeviceContext, IVulkanResourceUploader,
  IVulkanTexturePipeline, IVulkanShaderCompiler, data types
- IeCoreOpenGlInterfaces: IOpenGlContext contract
- IeCoreImGuiVulkan: VulkanImGuiRenderer, pipeline, shaders, GLSL compiler
- IeCoreImGuiOpenGl: OpenGLImGuiRenderer, shader program, GLStateGuard, shaders

Wiring:
- SilkNetVulkanWindow injects shared IVulkanResourceUploader + pipeline
- SilkNetOpenGlWindow implements IOpenGlContext, constructs OpenGLImGuiRenderer

Style:
- No block-scoped using (try/finally disposal per AGENTS.md)
- Explicit type names in new expressions
- sealed on Disposable classes (CA1063)
- TreatWarningsAsErrors in Debug for all new projects

- dotnet build Release: 0 compilation errors
- dotnet test: 13/13 passed
- No cycles between ImGui projects and SilkNet backends
