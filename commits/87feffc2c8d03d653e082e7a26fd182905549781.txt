message:
refactor: report camera registration refusals via CameraRegistrationResult
Register now returns a CameraRegistrationResult (status + human-readable
reason) instead of throwing, so duplicate-name refusals can be surfaced
by callers: DefaultScene logs the refusal at warning level and EditorUI
prints it when the orbit camera swap is refused. SetMain applies the main
role only when the camera is actually tracked by the registry, so a
name-conflict refusal cannot dangle the main role on an untracked camera
while a benign re-register of an already-tracked camera still works.
Tests updated to the result-based API (133 passing).
