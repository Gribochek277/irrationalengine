fix(audio): validate RIFF/WAVE magic in WavParser (PR #88 review P3)
FourCc.Riff/FourCc.Wave were declared but unused — Parse skipped the
12-byte header blindly and scanned for 'fmt ', so a non-WAV file that
happened to contain plausible chunk tags would decode into garbage instead
of throwing InvalidDataException as the doc comment promised
(ParseRejectsNonRiffBytes passed only incidentally: its junk had no fmt
chunk). Parse now asserts 'RIFF' at offset 0 and 'WAVE' at offset 8 and
rejects files shorter than the container header. Tests: corrupted RIFF
magic, corrupted WAVE tag, plausible chunks with XIFF magic, short header.

ADR updated: static per-clip buffer + narrow Play catch documented.
