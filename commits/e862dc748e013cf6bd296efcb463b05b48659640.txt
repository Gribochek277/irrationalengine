feat(gameplay): declarative state machine driving animation (#42)
Add a pure gameplay state machine — states, transitions on events and
polled guards, on-enter/on-exit hooks — shared by the player and enemies,
and a scene component that drives the object's animation from it.

- GameplayState/GameplayTransition/GameplayStateMachine live in
  IeCoreInterfaces.Gameplay + DefaultImplementations.Gameplay; a machine is
  built from a declarative table, self-transitions re-enter a state, and
  polled guards are rising-edge triggered.
- StateMachineComponent subscribes to the machine and plays each entered
  state's clip through IAnimationComponent.TryPlay(clip, crossFade); a
  missing clip is logged once per name.
- GameplayStateMachineUpdater ticks machines once per frame before the
  animation stage, so a transition renders on the same frame.
- AnimationComponent.TryPlay resolves a clip by asset name and cross-fades
  from the displayed pose via the pure BonePoseBlender.
- SceneObject wires animation into the state machine and starts machines
  after the other components have loaded, regardless of add order.
- Unit tests: transitions, guards, re-entry, hook order, animation drive,
  blending, the frame stage and the scene-object wiring.
- ADR docs/adr/gameplay-state-machine.md and CONTEXT glossary entries.
