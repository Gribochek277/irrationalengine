fix(audio): static per-clip OpenAL buffers, leak-safe upload, no NRE masking (PR #88 review P2/P3)
P2 — every Play() regenerated + re-uploaded the whole clip PCM (a 0.5 s
stereo@44.1k SFX is ~176 KB per shot) and deleted the buffer on each
stop/reap. Now one static buffer per AudioClip lives in an
OpenAlBufferCache (ConditionalWeakTable), created on first play and reused;
sources no longer own buffers. The uploader deletes the id it generated if
the upload fails after GenBuffers, and a failed upload stores nothing in
the cache (next play retries), so the earlier failure path can no longer
leak buffer ids until context teardown. Backed by a new
IeCoreAudioOpenAl.Tests project with counting-fake tests pinning: N plays
-> 1 upload, distinct clips -> distinct buffers, failed upload -> no entry,
DeleteAll frees every buffer.

P3 — Play's catch widened from 'AudioException or NullReferenceException'
to AudioException only: an NRE with the device available is a genuine
defect in the code/binding and must surface loudly, not be logged as a
play failure. CreateSource also cleans up a half-made source id on failure.

Live smoke re-verified on Linux (openal-soft): one-shot, replay reuses the
buffer (1 buffer after 2 plays), loop, stop, per-clip isolation.
