feat: render contract — Collect → Cull → Sort → Draw stages (#48)
Renderers walked the scene themselves and duplicated the geometry/material
decisions per backend. Introduce a backend-agnostic render pipeline both
backends consume as their draw input, so they draw exactly the same list.

- New project IeCoreRenderPipeline (no GPU types): DrawCall carries the
  scene object, model/material components, mesh, resolved material slot,
  combined index range and composed model matrix. Stages: Collector
  (scene walk → one call per (object, mesh)), Culler (pass-through now;
  frustum culling comes in #70), Sorter (stable by material slot then
  object name), RenderPipeline facade (collect → cull → sort).
- OpenGL: OnRender drains GetVisibleDrawCalls and draws one call per mesh;
  animation dedup per object per frame.
- Vulkan: same draw-call input; mesh/material/descriptor-set caches keyed
  by what the calls carry; animation dedup unchanged.
- DI: collector/culler/sorter/pipeline registered in IrrationalEngine.
- Tests: IeCoreRenderPipeline.Tests (collect/sort/composition, fake
  culler, 20 tests); renderer contract suites gain a render-pipeline
  ctor-guard test each. Full suite 202 passed, 0 warnings.

closes #48
